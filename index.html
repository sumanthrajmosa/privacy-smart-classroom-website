01 / Problem

Classrooms use energy even when no one needs it.

Manual attendance takes time, occupancy can be difficult to estimate, and lights or fans may remain on in empty areas. Camera-based automation also raises privacy questions that need to be considered from the beginning.

PROBLEM 01

Unnecessary energy use

Whole-room lighting and fans can run even when only part of a classroom is occupied.

PROBLEM 02

Limited occupancy visibility

Manual checks cannot always provide timely entry/exit counts or row-level occupancy estimates.

PROBLEM 03

Privacy and trust

Storing identifiable video creates risk. The design prioritizes local processing and count/event outputs.

02 / Architecture

From camera frames to energy decisions.

The proposed pipeline separates perception, movement counting, occupancy estimation, sensor rules, and the dashboard so each module can be tested independently.

STEP 01

Camera input

Capture frames from a compatible camera connected to the Raspberry Pi.

STEP 02

Person detection

YOLO detects people and produces bounding boxes.

STEP 03

Object tracking

ByteTrack associates detections and tracks movement over time.

STEP 04

Line crossing

A virtual door line estimates entering and exiting direction.

STEP 05

Occupancy + control

Counts and configured regions inform dashboard status and energy rules.

Architecture describes the proposed system. Hardware control and live analytics require implementation and validation.

03 / Method

Modular, edge-first processing.

The Raspberry Pi acts as the local controller. Computer vision provides person detections and tracks; sensor inputs and policy rules can then guide row-level appliance control.

A / PERCEPTION

YOLO + ByteTrack

Detect people, assign temporary track IDs, and use trajectory changes to estimate door-line crossings.

B / ENVIRONMENT

Sensor fusion

LDR and temperature readings can support lighting and fan decisions. An acoustic sensor can provide a noise-level signal.

C / APPLICATION

Dashboard + records

A web dashboard can display occupancy, attendance-related events, sensor readings, appliance state, and reports.

04 / Privacy

Occupancy, not identity.

Privacy-preserving design should minimize what is collected and retained. The system's intended purpose is room-level awareness and energy efficiency, not identifying students by face.

DESIGN PRINCIPLE

Process locally. Store less. Explain clearly.

The proposed system avoids face recognition and aims to keep video processing on the edge device. Store only necessary event data, control dashboard access, and define retention rules before deployment.

NO FACE RECOGNITION EDGE PROCESSING
✓Minimize retention
Do not save video unless there is a justified, approved need.
✓Restrict access
Use authentication for dashboards and records.
✓Be transparent
Tell classroom users what is detected and why.
✓Validate performance
Measure counting errors before relying on the system for decisions.
